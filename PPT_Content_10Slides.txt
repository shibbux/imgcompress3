SECTION B: Data Flow

User Uploads Image
        ↓
FileReader API converts to Data URL
        ↓
Image Object validates and loads
        ↓
Canvas API renders image
        ↓
Pixel Processing:
  - Apply filters (grayscale, sepia, blur)
  - Apply adjustments (brightness, contrast, saturation)
  - Apply watermark
  - Apply resizing
        ↓
Compression Engine:
  - canvas.toBlob() with quality parameter
  - Test file size
  - Iteratively adjust quality if needed
        ↓
Quality Analysis:
  - Calculate PSNR (Peak Signal-to-Noise Ratio)
  - Extract color palette
  - Compute compression metrics
        ↓
Export to Blob → Download or ZIP

EXPECTED QUESTIONS & ANSWERS:
Q: Why client-side only? Won't it be slow?
A: Client-side eliminates server costs/privacy concerns. Processing is 
   instantaneous (< 1s per 5MB) due to optimized Canvas API usage.

Q: How do you handle large images?
A: Browser can handle images up to GPU memory limits (~200MB on modern devices).
   Canvas API provides efficient pixel-level access.

Q: What about offline usage?
A: Currently works in browser memory. Future PWA version will enable offline.

Q: How is privacy maintained?
A: No data leaves user's browser. No servers, no logging, no data transmission.
   localStorage only stores user preferences locally.

Q: What about format support?
A: Input: JPEG, PNG, WebP, BMP, AVIF
   Output: Same formats + conversion between them
   Codec support depends on browser (all modern browsers support these)

Q: How does PSNR calculation work?
A: Compares original vs compressed pixel-by-pixel, calculates Mean Squared Error,
   applies PSNR formula. Scores above 40dB are imperceptible to human eye.

Q: Can this handle batch processing?
A: Yes! Up to 50+ images, same settings applied to all, ZIP download with
   organized folder structure.

Q: What's the cost model?
A: Currently 100% free. Can be monetized later with freemium tier or enterprise.
